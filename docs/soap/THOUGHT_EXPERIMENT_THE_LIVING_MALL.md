# 思想实验：「活商场」—— SOAP 是否成立的判据

> **命题**：若下列场景能在工程上**同时跑通**（允许延迟、权限与商业合同在圈定范围内解决），则在**操作意义上**可以宣称：**SOAP 作为空间智能体时代的接口层成立**。  
> 本文是**思想实验**：不假设今日已全部实现，而是把**必须被 SOAP（及配套 Profile）说清的东西**列全，便于 spec 与 Tier 对齐。

---

## 一、场景速写：同一物理商场，多重平行现实

**地点**：某大型商场中庭与相连铺面。

| 参与者 | 在做什么 |
|--------|-----------|
| **玩家 A** | 戴 **MR 眼镜**，玩「平行世界」LBS 游戏：虚拟怪、任务点叠在真实柱子上。 |
| **顾客 B** | 用 **手机**扫门店海报，进入该店的 **1:1 数字孪生** 预览与领券。 |
| **顾客 C** | 戴 **AI 眼镜**，语音导航 + 与店员的 AI 分身对话。 |
| **机器人 D** | **具身智能**单元在通道巡检、送货；避让行人。 |
| **线上世界 E** | **虚拟商场**与物理布局 **1:1**，里面有 **NPC 智能体**「生活」、接单、社交。 |
| **玩家 A（再次）** | MR 里不仅能看游戏层，还能 **看到** 线上 NPC 在「对应真实坐标」上的化身（经授权与渲染策略）。 |

**压力点**：六类端侧、三条网络路径（边缘/云）、至少两套渲染管线（光栅/GS）和一套机器人控制栈——**没有统一契约，集成成本指数爆炸**。

---

## 二、SOAP 要扛住什么（按协议栈映射）

### L1 承载：同一商场，多份「真值」怎么共存？

- 物理商场 **CAD/BIM/扫描**、手机 **SLAM 局部图**、眼镜 **世界锁定锚点**、云端 **3DGS / 游戏引擎场景** 必须能挂在 **同一 `space_id` 下的不同 Payload Profile** 上（例如 `gltf+hierarchy`、`gaussian_splat`、`engine:unity`）。  
- **增量更新**：某门店装修后，孪生与导航图只同步 **变更子图**，不全量重推。  
- **虚实标签**：物体是 `physical` / `virtual` / `mixed`（如 AR 桌+真椅子）必须在场景图里 **可机读**。

**若做不到**：MR 与手机与机器人 **各说各的坐标**，NPC 无法被「钉」在同一根柱子旁。

### L2 上下文：Agent「指哪打哪」不歧义

- **Spatial URI**：`soap://mall_01/atrium/pillar_03`、`soap://mall_01/store_102/shelf_a` —— 游戏任务、导航、机器人取货 **共用语义地址**。  
- **拓扑 + 可供性**：通道可通行、货架可取放、柱子可挂 AR 锚——**不必**所有端都跑同一物理引擎，但 **动词与禁区**要对齐。  
- **记忆引用**：NPC「记得上周在这家店促销」——轨迹与事件 **外挂到 URI**，不污染几何文件。

**若做不到**：AI 眼镜说的「那家店」与线上 NPC 说的「那家店」不是同一对象。

### L3 行为：动词少、映射多

- 同一动词 **`OBSERVE` / `NAVIGATE` / `MANIPULATE` / `REARRANGE`**（v0.1 子集）由 **Driver** 映射到：游戏引擎位移、机器人 SDK、IoT 门锁、眼镜 UI。  
- **标准错误码**：碰撞、不可达、权限拒绝、虚拟物体与物理锁冲突——**NPC、玩家 Agent、机器人** 都能解析并写进日志/记忆。

**若做不到**：线上 NPC 发起的一个动作，线下无法解释失败原因。

### L4 协同：多人、多 Agent、抢同一资源

- **物体锁 / 区域锁**：机器人要进后场通道时，与清洁 Agent **协商或排队**；MR 游戏不占物理机器人路径 **由策略配置，但锁语义一致**。  
- **意图广播（可选）**：「我打算坐在长椅 7」——减少互撞与鬼畜动画。

**若做不到**：同一中庭里 **人、机、虚拟体** 行为不可预测。

### L5 画像：商场 Profile

- **延迟 SLA**：眼镜端 T2、云端 NPC T3；**显式声明**，避免把云延迟强加给安全关键机器人。  
- **合规**：摄像头、生物特征、未成年人游戏区域——**权限模型**挂在 URI 或区域上。

## 三、「顺利运行」的可检验定义（避免玄学）

思想实验 **通过**，当且仅当（在试点范围内）能演示：

1. **同一 `space_id`** 下，至少 **三类端**（例：手机 Web、MR、云端 Agent）读取 **同一份或可追溯对齐的 SOAP 场景图**，对 **同一 URI** 查询得到 **一致语义**（类型、区域、虚实属性）。  
2. **至少一条跨虚实动作闭环**：例如云端 NPC 通过 SOAP 动作触发门店 IoT（灯/屏）或 **孪生状态变更**，MR 用户在 **授权后** 能看到状态变化。  
3. **至少一次冲突可解释**：人工改变物理世界后，孪生 **按「真实世界优先」规则** 收敛，并产生 **标准错误/同步码** 供 Agent 消化。  
4. **具身单元**接收的 **目标 URI** 与导航图 **可映射**（在声明的 Tier 内误差有界）。

不要求：全网毫秒级一致、所有引擎像素级对齐、所有公司共享模型权重。

## 四、与 Conformance Tier 的对应

| Tier | 在「活商场」里意味着什么 |
|------|-------------------------|
| **T1** | 大家 **指同一店、同一柱、同一 NPC 槽位** 不打架。 |
| **T2** | 手机/MR/云 **几何大致对齐**（包围盒/锚点），能做过门、过柱的粗略路径。 |
| **T3** | 装修、IoT、孪生 **时间线可合并**；「谁真谁假」有规则。 |
| **T4** | 流式状态 + 锁 + 延迟 SLA——**高峰时段**仍可控（最难，可分期）。 |

**SOAP v0.1 先锁 T1**，为思想实验提供 **最小可讲故事的骨架**；商场全量 T4 是 **路线图终点**，不是首版承诺。

---

## 五、若实验失败，最可能卡在哪（便于排雷）

1. **没有权威 space_id 与锚点注册**（物业/平台不愿开放）。  
2. **只有几何、没有 URI 与本体**（又回到点云孤岛）。  
3. **各厂动词各自扩展、无错误码**（调试地狱）。  
4. **把「世界模型能力」误当成「协议能力」**（期望协议解决推理质量）。

---

## 六、结语

「活商场」不是营销画面，而是 **SOAP 的 Fermi 估算**：若连叙事都圆不上，spec 一定漏了层；若叙事圆上而工程分阶段可测，**我们就走在对的路上**。
